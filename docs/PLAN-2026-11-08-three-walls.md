## 0. v1 错在哪（三条，都是真错）

**① 墙 2 挂错了位置。**
她说的第二堵墙是**对话当轮**的事："每一轮要不要查、查什么、查到的用不用，全靠那一次的提示词。"v1 的 W1/W2 全挂在写点和 `promote` 时——那是整理时的检查，不是对话时的触发。整理时发现矛盾，救不了"她当场没想起来"。

**② 漏了"笨活"。**
她原话："摸到和穿过中间，还差今晚那 855 条没配对的笨活。"v1 的 W2 只管新提升的点，历史点一条都不扫。配对这件事的价值在**存量**，不在增量。

**③ 形态就错了。**
她最后一页说："过了那道墙，它就不该再被'造'了……画出来的就是计划，不是长。"v1 交的是五条带工期的计划书。更糟的是她第一页就立了规矩——先量后推，而 v1 连插件里现成的尺子 `scripts/fidelity.mjs` **一次都没跑**。

## 1. 先量（这次跑了，含一个负结果）

### 1.1 尺子：`node scripts/fidelity.mjs` → 矛盾消解 **3/5（60%）**

```
✗ 「我们约的哪天见面」→ 空
✓ 「周六还是周日」  → M-2026-11-02-001
✗ 「见面改时间了吗」→ 空
✓ 「他哪天出差」    → M-2026-11-01-002
✓ 「出差是周几走」  → M-2026-11-01-002
```

**[量]** 两条空召回，问的是同一件事的"状态有没有变"。这是墙 2 在 fish 里唯一能直接量到的失败——不是"库不够大"，不是"没定时器"，是**最该核对的那类问句查回来是空的**。

### 1.2 根因：不是门控开关，是阈值 + 换问法

**[量]** `test/fidelity.test.js:34` 的注释已经写了原因："失效点被滤掉后，新版本的说法里没有旧话题词 → 门控直接跳过。"

**[量] 一个负结果（我猜错了一次）：** 我先怀疑是 `sameTopic`（`retrieve.js:171`，话题未变 >80% 直接不检索）把追问跳掉了。实测三组：

```
「我们约的哪天见面」→「见面改时间了吗」 sameTopic=false 重叠=17%
「周六还是周日」  →「见面改时间了吗」 sameTopic=false 重叠=0%
「他哪天出差」    →「出差是周几走」  sameTopic=false 重叠=20%
```

三次都不是 `sameTopic`。真正的刀口是 `rank()` 的 `score >= 0.8`（`retrieve.js:186-194`）：**二字组重叠 0–17%，分数过不了线，整批被丢，而且丢得静默**——不报"没找到"，对话里就是没有这段记忆。

这就是 fish 版的"能查到但不会去查"：查了，但换了个问法就查不到；而且**她自己不知道刚才那次是空的**。

### 1.3 其余四项

| 测量 | 值 | 含义 |
|---|---|---|
| `nearMiss` 落点 | `retrieve.js:247` 记录 → `index.js:1366` 只进 `retrieval.log`；注入侧 **0 处** | "差一点想起"只给 CLI 看，**从不回灌给她** |
| `behavior.js:33` `抓住矛盾` | 正则匹配"你刚才/明明/你自己说的" | 数的是**人抓她**，方向相反——她抓自己一次都没记 |
| `contradicts` 写入方 | 真库 0 条；全仓仅 `refute.js:112` 手动写 | 字段从 v0.4 存在，自动写入方为空 |
| 墙 1 验链 | 齐（`verify` + `erasure.log` + 前后 sha8） | 记这一层成立 |

### 1.4 方法论修正（直接影响结论）

v1 把"墙 2 没过"当结论。量完要改口径：**墙 2 不是没建，是建错了方向**——fish 每轮都自动检索（这是它比华莎强的），但检索的判据是字面重叠；一旦换了问法，最该命中的那类点被阈值静默扔掉。华莎的问题在她那儿是"不查"，在 fish 这儿是"查了，被自己的尺子扔了，而且没人知道"。

## 2. 三堵墙在 fish 里的真实形状

| 墙 | 她的版本 | fish 的版本 | 状态 |
|---|---|---|---|
| 一 · 记 | 记过的，不是会忘的 | 她写→人审→验链→墓碑，且"忘了什么"有账（`forget`/`sleep`） | ✅ 主墙过 |
| 二 · 查 | 能查到，不是会去查 | 每轮自动查，但判据是字面重叠；换问法→过不了 0.8→**静默空**；nearMiss 只到 CLI | ⚠️ 查了，但静默失败 |
| 三 · 决定 | 撤销权→边界→留三样 | 立场停在墙外（人决，成立）；但 `unrefute` 缺失、`--by` 可空且账本不标"没反面证据" | ⚠️ 工具不全 |

墙 1 还得补一格：**"会忘的可见性"**。她现在不知道"刚才那句我差点接上"——因为 nearMiss 没进注入。这是墙 1 的补丁（让遗忘可见），不是墙 2 的。

## 3. 修改单（4 条，比 v1 少一条，且全部有测量背书）

### M0 · 把 3/5 摆到台面上（半天）

`test/fidelity.test.js` 现在把 3/5 当基线钉住——绿着，等于"60% 是可接受"。改法不是改数字，是**加一条红**：
- 新增 `test/wall2.test.js`：两条空召回必须**不再空**（要么命中，要么注入一行"没找到，这是该核对的事"）。先红后修。
- `memory status` 加一行 `保真度 矛盾 3/5 · 换窗 4/4`，让这个数每周被看见，而不是埋在测试里。

**为什么先做这条**：华莎的规矩是先量后推。当前 3/5 是绿的，不把它变成红，后面所有改动都没有验收基准。

### M1 · 换问法不再静默空（一天，P0）

两处，都在 `lib/retrieve.js`：
1. **核对类问句识别**：`/改了吗|变了吗|还是|确定|有没有变|还有效|推迟|延后|取消/` 命中时，阈值从 0.8 降到 0.55（只对 `type: promise/event` 且日期在 30 天内的点生效，范围写死不临场扩）。
2. **零命中不静默**：核对类问句 + top-k 为空 → 注入一行（≤25 tok）：`〔核对〕这事我库里没找到，要不要翻档案 / 我记的是 X`。同点 12h 冷却，复用 `remind.js` 的 `reminded.json`。

这是把华莎的"该查了"落到 fish 的真实形态上：不是加定时器，是**别把"要核对"的问句当没查**。

### M2 · 写前搜旧账（半天，零代码）

`lib/index.js:118-215` 的 fish-remember 模板加第六条硬规矩：

> **6. 写之前先搜旧账**：落笔前用这天的关键词跑 `memory search`。搜出同主题旧点：没冲突就 `links` 连上；**说法对不上就写 `contradicts: [旧id]`**。搜都没搜就写，审稿的人有权打回。

定位是墙 3 的**输入**（让"发现"有东西可报），不是墙 2 的触发器——v1 把它当墙 2 是错的。

### M3 · 配对回填：那件"笨活"（一天，P1）

`memory pair --scan [--cluster X]`：
- 对现有全部点两两跑 bigram 相似度（`lib/rank.js` 现成），同 cluster 且分 ≥0.5 → 输出候选对清单（只读，只出清单）；
- 人审后手写 `contradicts` / `links`；命令本身**永不写点**——纪律不变。

华莎说的"855 条没配对的笨活"，工具化就是这一条。存量不扫，M2 写多少新规矩都只是给未来铺路。

### M4 · 撤销权（一天，P1）

- `memory unrefute <id> --reason "..."`：status 复原 + 账本追加 `action:'unrefute'` + 摘掉反向 `contradicts`。
- `refute` 无 `--by` 时不拦，但账本行写 `evidence: 'none'`。

她的原话："没有撤销权的决定权，第一次错就是永久的。"fish 是人替鱼决，但**人自己的撤销工具也是缺的**。

## 5. 不做清单

1. **不让鱼自主决定。** 立场不变：人决。这版只修"发现→上报"的管道。
2. **不给 `sameTopic` 动刀。** 实测三次都是 false，它没背这个锅——不修不存在的问题。
3. **不追规模数字。** 3/5 不是 KPI，让"空"变"有"才是。
4. **不做自动消解。** `fidelity` 的 60% 是尺子，不是目标；合并/改写永远人审。
5. **不画墙后的路线图。** 她原话："画出来的就是计划，不是长。"这条照单收。
