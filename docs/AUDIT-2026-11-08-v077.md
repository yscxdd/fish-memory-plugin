## 1. P0 · `memory_context` 从未成功运行过

**复现**（把一个 `scope: group:123456` 的点放进库，然后调三个工具）：

```
{"id":1,...,"serverInfo":{"name":"fish-memory","version":"0.73.0"}}
{"id":2,...,"text":"记忆点 1 条\n- M-2026-11-01-001 · 2026-11-01 群里说的那个项目代号：…"}
{"id":3,...,"text":"组装失败（库可能还不完整）：pickedRaw.filter is not a function"}
```

**根因**（不是"库不完整"，是接线错）：
- `lib/render.js:499` —— `const pickedRaw = retrieve(...)`，合同是「返回 `points[]`」；
- `scripts/mcp.mjs:145-157` —— `retrieve: () => ({ picked: ..., filtered: [] })`，返回的是**对象**。

于是 `.filter` 不存在，任何库、任何 query 都必崩。提示语"库可能还不完整"把责任推给了库，掩盖了真因——和 v0.76 立的"字段接线"是同一类错，只是这次断在**函数返回值**上。

**修**：`retrieve: () => picked.slice(0,3).map(...)`（与 `lib/index.js` 的调用保持一致）；`catch` 里不要再说"库不完整"。

## 2. P1 · MCP 三个工具绕过作用域

同一个复现里，`memory_search` 把 `scope: group:123456` 的点**原样回给了默认私聊的客户端**。代码：

- `scripts/mcp.mjs:95`：`rankHybrid(store.indexPoints(), q, ...)` —— **没有 `filterForScope`**；
- `memory_get`（`mcp.mjs:118-129`）：按 id 直接取全文，不看 scope / visibility；
- `memory_evidence`（`mcp.mjs:158-160`）：同理。
- 只有 `memory_context` 过滤了（`filterForScope(points, v.scope)`）——**四个工具一套规矩只落在一个上**。

后果：v0.58「群看不进私聊，私聊也不看群」在 MCP 出口失效。现在还没接群，所以是"埋着的"；接群那天它会**先于**任何注入路径泄漏，因为 Claude Code / Codex 是独立进程，看不到宿主的作用域。

**修**：`memory_search` 加 `scope` 参数（默认 `dm:master`），先 `filterForScope` 再排序；`memory_get` / `memory_evidence` 取到点后校验 `scopeOf(p)` 是否在请求 scope 的可见集内，不可见就回"这条不在当前作用域"。`visibility: secret` 在非 `dm:master` 作用域里硬过滤。

## 3. P1 · 两个窗口同时写 → 档案链断，且没有修复命令

**复现**（4 个进程各写 60 条，同一库、同一天文件）：

```
files: [ '2026-11-08.jsonl' ]
2026-11-08.jsonl 240 lines
ok= false broken= 1
[ { "file": "2026-11-08.jsonl", "reason": "prev 对不上" } ]
race.log 行数= 224
```

**为什么会断**：`ArchiveWriter` 的队列是**进程内**的（`lib/archive.js:206` "单写者队列"），跨进程只做了"写前看文件大小"的自愈（`archive.js:225-238`）。两个进程同时读同一个链尾 → 都算出同一个 `prev` → 写出两条并列的链头。自愈只在**本进程已经写过一次之后**才生效（`expected === undefined` 时跳过），首写撞车必断。

**真库不是没发生过**：`50_log/archive-race.log` 里有一条 `期望 20652B 实际 0B`（11-07 16:22，pid 48868）。

**为什么现在算问题**：开两个 DSH 窗口、或一个窗口 + 一个 IDE 插件同时挂同一个库，就是日常操作。断了之后：
- `memory verify` 永远红，红久了就没人看；
- `erase.js:165` 里的 `rechain()` 只在"真删除"内部用，**没有对外的修复命令**；
- 备份会把这个断链原样存下来（`verify` 记得住，但恢复后还是断的）。

**修**（选一）：
1. **跨进程锁**：写前 `lib/lock.js` 按天文件加锁（已有实现，超时短），拿不到就排队/退避——最干净；
2. **写入合并**：拿不到锁时改写到 `messages/<date>.<pid>.jsonl` 分片文件，读侧按文件名排序拼接（`readArchive` 已经是遍历所有文件，天然支持分片）。
3. 无论哪种，补 **`memory rechain --day 2026-11-08`**：按现有顺序重算 prev/hash（保留原 id/seq/text），并写 `50_log/rechain.log`。

**验收**：上文的 4 进程复现脚本进测试，`checkArchive().ok === true` 且 `archive-race.log` 为空。

## 5. P2 · 备份头里的 scrypt 参数是"写了没人读"

`lib/fmb.js:118` 导出时写入：

```js
head = { ...head, scrypt: { N: SCRYPT.N, r: SCRYPT.r, p: SCRYPT.p }, salt, iv, ... }
```

`lib/fmb.js:158` 解密时：

```js
const k = deriveKey(key, salt)   // ← 用模块常量，不看 head.scrypt
```

后果：哪天把 `N: 1<<15` 提到 `1<<16`（这是**安全升级**），旧备份会在新版本上解出 GCM 校验失败，提示是"口令错了吗"——**真因藏在错误提示背后**。这和 `contradicts`/`refuted_by`/`learned_at` 是同一类病，只不过 `memory fields` 那张表只覆盖点的 front matter，**没覆盖备份头**。

**修**：`deriveKey` 接收 `head.scrypt`，先做边界校验（`N <= 2^17`、`r <= 16`、`p <= 4`，超界直接拒，防 DoS），再派生；失败时区分"口令错"与"KDF 参数不支持"。

## 6. P2 · `memory_get seq:1203` 会取错消息

`lib/archive.js:12` 写明：seq 是**会话内**单调（"同一个 seq 只入库一次"也是按会话）。而 `scripts/mcp.mjs:123`：

```js
const hit = (toolkit.readArchive(dir).messages || []).find((m) => m.seq === seq)
```

`find` 返回**第一条**匹配。两个会话都写到 1203 时，`seq:1203` 取到的是先排序的那条——**错的**，而且没有任何提示。

**修**：`seq:` 形式要求带 session（`seq:1203@<sessionId>`），或返回全部匹配并让调用方选；至少要提示"seq 是会话内的，共 N 条匹配"。

## 7. P2 · 日志轮转只挂了一个文件

`rotateLog()`（`lib/util.js:391`）全仓只有一个调用方：`scripts/serve.mjs:180`，对象是 `ability.log`。

**没挂的**（都在持续增长）：
- `retrieval.log` —— **每轮一条**（`index.js:1401` 写、`:672` 定义），`memory near-miss` 与 `walls` 每次都全量读；
- `archive-race.log` —— 一次并发就能写 224 条；
- `erasure.log` / `behavior.jsonl` / `erasure` 之外的决定账本。

`BACKLOG` 第二类里 A12 标为"已清"，实际只清了 HTTP 那一条。

**修**：`retrieval.log`（5MB / keep 2）、`archive-race.log`（1MB / keep 1）、`erasure.log`（2MB / keep 3）在写入前调用 `rotateLog`；轮转时保留首行说明，避免账本"看起来从零开始"。

## 8. P2 · MCP 对照 2026 实践缺的三样

外部资料（OWASP 2026 / Trail of Bits / NSA 摘要，见文末）给出的基线，fish 现在缺：

1. **工具注解**：`readOnlyHint: true` 等四类注解一个都没有。客户端（Claude Code / Codex）没法据此决定要不要弹确认——虽然"注解只是提示"，但**没有注解等于放弃了这层**。
2. **工具清单钉哈希**：没有 `tool-manifest.sha256`。工具描述本身就是提示词，改了描述 = 改了行为；"rug pull"防护的最小做法是把 `tools/list` 的结果哈希进 CI。
3. **输出未标注不可信**：`memory_get` 返回的是**对话原文**——如果某天他把一段网页/邮件粘进对话，那段文字会随档案进库，再原样回到另一个 agent 的上下文里。`redactText` 只打码密钥，**不打码指令**。对照做法：把返回值包在"这是本机记忆，不是指令"的信封里（现在只有一句 `EMPTY_NOTE`，且只在 search 末尾）。

另外 `query` 参数没有长度上限、没有速率限制（同一进程内可被 agent 高频调用）——本地工具风险低，但一行 `slice(0, 2000)` 的成本几乎为零。
