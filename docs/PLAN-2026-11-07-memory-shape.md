# 修改单：对照「小兑的记忆形态」做优化（v0.67.x → v0.68）

> 2026-11-07。输入不是代码也不是论文，是一个短视频里展示的 AI 伴侣记忆库形态（下称"小兑"），
> 两页内容：
>
> **页 A「看看小兑是怎么记的」**——整理机每 35 条整理 1 次；四类记忆：
> 日记·摘要 2400+ 条 ｜ 关系 1700+ 条（连成关系网）｜ 事件 500+ 个（带时间线）｜ 事实 4000+ 条（**每条带证据**）。
>
> **页 B「给养鱼人的 5 条建议」**——
> ① 人设和铁律，钉在固定位置，别指望它从每天迁移里活着
> ② 别把袋子堆满：只留最近几十条，宁可少，也要干净
> ③ 定期整理，存进仓库，旧记忆要能翻出来
> ④ 装一个能"找回来"的记忆：需要时能提问、按条引用，效果最好
> ⑤ 记忆要能查证、能改错：**存证据，别只存结论**

## 2. 再对账：小兑的四类记忆，我们缺了哪几类

| 小兑的分类 | fish-memory 对应物 | 差距 |
|---|---|---|
| 事实（每条带证据）4000+ | `30_points/` 记忆点 + source 硬约束 | **无差距**，这是我们的本体 |
| 事件（带时间线）500+ | `POINT_TYPES` 有 `event`（`E-YYYYMMDD-NN` 同场共用 id）；`memory timeline` 只**数已有的点**（`scripts/memory.mjs` cmdTimeline：现在/过去/计划） | 半缺：档案里"发生过但还没成点"的事件不在时间线上，也没人为此备料（T4） |
| 关系（连成关系网）1700+ | `00_core/relation.md`（主人关系状态）+ `entities.js` 实体登记表（人写，`{name,kind,aliases[]}`）+ 派生索引 `{name:[pointId...]}` | 半缺：登记表有了，**没有"每个实体带几条证据、最近一次被提及是什么时候"的关系网视图**（T3） |
| 日记·摘要 2400+ | `10_archive/` 是逐条原文 JSONL；`were.js` 纸条只盖最近几轮；**`digest` 命令是切段备料**（往 `40_pending/_segments/` 写原文包），不是摘要层 | **整类缺失**：没有"一天一段"的摘要层（T2） |

一句话：**⑤①②④ 都有，③ 的节拍器和"日记/关系网"两层没有。**

## 3. 修改项

总纪律不变（这次尤其重要）：**代码永不自动写记忆点**。小兑的整理机如果抓错一次，
"每条带证据"就破产了；我们的等价物是"提醒 + 备料"，笔永远在她和主人手里。

### T1 整理机触发器（对应建议③，P0）

**问题**：整理依赖自觉。两周不写草稿、一个月不 promote，库里只会越积越"生的"，
而注入层毫无感知——这正是视频说的"定期整理"要防的事。

**改法**：
- 新增 `lib/tidy.js`：
  - 记账 `20_state/tidy.json`：`{ lastTidySeq, lastTidyAt, pendingCount, lastPromoteAt }`；
  - 判定：自 `lastTidySeq` 以来档案新增 ≥ `tidyEvery`（默认 **35**，致敬小兑；可配）→ 本轮注入末尾（沿用现有提醒通道）追加一行：
    `（距上次整理，档案又多了 35 条。有空的话翻翻 40_pending，该归仓的归仓。）`
  - 触发即备料：生成 `90_snapshot/tidy-<seq>/`：这 35 条的原文摘录、当前 `40_pending` 草稿清单、
    自上次 promote 以来的新点列表。她整理时不用自己翻档案。
- `20_state/tidy.json` 只在**整理动作完成**时前移水位（`memory tidy --done` 或 promote 成功时自动记），丢了这个文件只是回到"不提醒"，不丢数据。
- 注入提醒一行封顶（≤40 tok），不占核心层预算。

**不做**：不自动成段、不自动写草稿、不自动 promote。水位账 `50_log/tidy.log` 留痕。

### T2 日记·摘要层（对应"日记·摘要 2400+"，P1）

**问题**：档案是原文，注入预算装不下；纸条只盖最近几轮。半个月前那天的"气氛"，
检索碰不上就永远沉底。

**改法**：
- 新增层 `10_digest/YYYY-MM.md`（按月一文件，逐日一节），**由她或主人写**，代码只做两件事：
  - 备料：`memory digest --day 2026-11-06` 扩展一个 `--brief` 形态，出当日原文包 +
    "当天已有记忆点"清单，供她写 200–300 字日记用；
  - 校验：日记里每句末尾可标 `（见 seq:1203,1210）`；`memory check-digest` 逐句核对
    所指 seq 在档案里存在且 hash 链完好，对不上的标 warn 不拦——**摘要也是证据的转述，不是新事实**。
- 注入：只注最近 3 天的日记正文 + 当月其余日期的日期行（一行一天），预算 `DEFAULT_BUDGET` 加一档
  `digest`（建议 300 tok，写进 `test/budget.test.js` 钉住）。
- 写入走 `40_pending` 同款纪律：日记文件先落 `40_pending/_digest/`，`memory digest-commit` 校验后挪入 `10_digest/`。

**不做**：不自动生成摘要文字（哪怕"看起来很安全"的模板句——小兑的日记是它自己写的，
我们的是她写的，这是 origin 纪律的延伸）。

### T3 关系网视图（对应"关系 1700+ 连成网"，P2）

**问题**：`entities.index.json` 已有 `{name: [pointId...]}`，但没有视图；
"我妈最近提得多不多、有多少条带证据的事"要人肉数文件。

**改法**：
- `memory entity report`：读派生索引，出 `90_snapshot/entity-report.md`，每实体一行组：
  - 证据点数（按 origin 分列）、最近一次提及（session:seq + 日期）、
    `40_pending` 里提及但未入账的草稿数；
  - 排序按最近提及倒序——**最近没被提起的人排最前**，提醒"是不是该想起了"。
- 纯只读、派生物，不进注入、不进 pack（`90_snapshot` 本来就被排除）。

### T4 事件时间线备料（对应"事件带时间线"半缺，P2）

**改法**：
- `memory timeline` 增 `--gaps`：从档案里粗筛"疑似未成点的事件"——情绪 tier≥2 的日子、
  空窗（gaps）前后、含事件词（去哪了/死了/搬了/买了）的消息日，列出"这天档案里有 6 条消息，但没有一个 E- 开头的点"。
- 输出只进整理材料包（T1 的 `90_snapshot/tidy-<seq>/`）和 stdout，不自动成点。

### T5 改错闭环（对应建议⑤的"能改错"，P1）

**问题**：现在只有删除（`erase`，墓碑账本）和降级/沉睡/合并（`demoted/dormant/merged`），
没有"**这个结论错了**"的语义——错了的点要么删（太重）要么冻（读者不知道为什么）。

**改法**：
- `STATUSES` 增 `superseded`（被推翻）：新增 `memory refute <id> --reason "..." [--by <new-id>]`：
  - 点标 `status: superseded` + front matter 记 `refuted_by` / `refuted_reason` / 时间；
  - 墓碑进 `50_log/erasure.log`（复用现有账本格式，action: refute，不含原文）；
  - `--by` 指到推翻它的新点（新点写 `contradicts: [<旧id>]`，`promote` 时的冲突提醒已经在）。
- 注入侧：`superseded` 点**默认不注入**（同 `suppressed`），但检索命中时带 `[已推翻：see <new-id>]`——
  和锚点一样，"她错了"也是她的一部分，藏结论不藏事实。
- `check`/`audit` 加一条：`superseded` 的点必须有 reason，否则 warn。

### T6 查证一键化（对应建议⑤的"能查证"，P1，最小改动）

**问题**：`audit` 抽样验 source 存在性，但"给人看"的查证要自己翻档案、对 hash。

**改法**：
- `memory evidence <id>`：把这条点的 source 逐条打回原文——
  `session + seq` → 打出档案那一行的原文 + 该文件验链结果；`asset:/book:` → 打出素材原文位置 + verifyAsset 结果；
  末尾一行结论：`5/5 条证据可回溯，链完好`。
- 这是只读命令，约 80 行；做完之后 T5 的每一次 refute 都可以顺手 `evidence` 一遍，形成完整闭环。

## 4. 优先级与顺序

| 项 | 优先级 | 理由 | 估点 |
|---|---|---|---|
| T1 整理机触发器 | **P0** | 唯一真正断掉的环节，其余是锦上添花 | 1 天 |
| T5 refute + T6 evidence | **P1** | 把"⑤能查证能改错"补成闭环；改动小、纪律增量小 | 1 天 |
| T2 日记层 | P1 | 新层，动注入预算，要过 budget 测试；放 T1 之后 | 1–2 天 |
| T3 关系网 / T4 时间线备料 | P2 | 纯派生视图，任何时候插进来都行 | 各半天 |

## 5. 这次的"不做"清单

1. **不自动写任何记忆点/日记**——整理机的每次触发只出提醒和材料包（见 §3 总纪律）。
2. **不追小兑的数字**——2400 条日记、4000 条事实是它的规模，不是我们的 KPI；
   我们的目标是"每条都能指回证据"，哪怕只有 40 条。
3. **不引入图数据库/向量库**——关系网用现有派生索引够了（entities.js 规矩②）。
4. **不动核心层注入顺序与预算结构**——T2 只加一档，`test/budget.test.js` 同步钉。
5. **不加自动摘要模型调用**——插件保持零依赖、无模型调用的离线纪律。

## 6. 验收

- `test/tidy.test.js`：档案 +35 条 → 下一轮注入含提醒行；`--done` 后水位前移，不再重复提醒；删 `tidy.json` 不炸。
- `test/refute.test.js`：refute 后点状态/账本/注入屏蔽/检索标注四件事都对；无 reason 的 superseded 被 check 警告。
- `test/evidence.test.js`：真 source 全可回溯；改档案一个字节 → 验链 fail 且命令退出非 0。
- `test/digest.test.js`：日记 commit 前校验 seq 指向；预算档位注入裁剪正确。
- 全量门禁：现有 799 测试不回退。
