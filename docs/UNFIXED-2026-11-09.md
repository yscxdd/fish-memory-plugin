## 二、不修的项

### B10（🟡）情绪极性反转会让"烦死了"变成开心

`lib/emotion.js` 的 `negated` 扫**全文**，而极性按**主句**算，命中否定词就把整体 valence 乘 −1。
"烦死了，不想干了" → 否定词命中 → 翻成 +0.6。

**为什么不修这次**：这不是"接线错"，是**情感词典的判定模型要重做**——
正确做法是"只反转被否定的那个词"，那要求词典里每个词带 `negatable` 标记。
改动面大于这一轮所有修复之和；而且没有真实对话数据时调它，等于凭感觉改她的性格。
**触发条件**：出现"你说难受她还高兴" → 那时按真实样本改。

### B13（🟡）erase 写盘被跳过时，墓碑仍记"已删"

`erase.js` 遇到并发写入会 `skipped`，但墓碑仍逐条记 `kind:'message'`、返回 `removed: N`。
**为什么不修**：修法清楚（跳过时墓碑标 `skipped: true`、`removed: 0`），但它改的是
`erasure.log` 的字段口径——**而这轮刚把这条路径改成"宁可跳过也不丢消息"**。
先让它不丢，再让它说得准；下一版连字段一起改（约 5 行 + 一条对账测试）。

### B14（🟡）UTC / 本地日期混用，跨午夜漂 ±1 天

`Date.parse('2026-11-09')` 按 UTC 零点解析；`toISOString().slice(0,10)` 也是 UTC。
UTC+8 下"今天的点"在 08:00 前会被算成昨天。

**为什么不修**：`time.js` 已有 `parseLocalDateMs`，但要用的地方散在
`forget.js` / `soul.js` / `toolkit.js` / `handoff.js` 四处，**每一处都得单独判断"这个日期是本地语义还是 UTC 语义"**。
一次改完风险高（tz-check 只覆盖了一部分路径）。
**触发条件**：出现"昨天的承诺今天没提醒"或"差一天" → 按文件逐个改，每改一个补一条 tz 用例。

### P1 / P7（🟡）`memory_recall` / `memory_get seq:` 每次全量读档案

每次 `readArchive` = readdir + 全量 `JSON.parse` + 排序，而工具超时设的是 3 秒。

**为什么不修**：正确修法是"按 mtime 缓存已解析的旧日文件"（照 `store.indexPoints()` 的写法），
但**没有大库基线就优化等于猜**。
**触发条件**：`retrieval.log` 里该工具超过 1 秒，或档案过 5 万条。

### P2 / B4（🟡）全局锁 `withLock` 没跟上按天锁的三处修法

`lock.js` 仍然：unlink 释放（本机 240ms/次）、只写裸 pid（pid 复用误判）、
`writeSync` 失败会留下空锁并要等 5 分钟才接管。

**为什么不修**：正确做法是"把两个锁实现收敛成一份"——那是重构，不是修 bug。
现在只是慢，不是错（`flush()` 每轮多付一次删除）。
**触发条件**：注入延迟可感知，或出现"写锁超时"日志 → 把 `withDayLock` 抽成 `lib/daylock.js` 复用。

### P3 / P4（🟡）`cursorOf` 每条消息读盘 + 每轮注入 10–20 次同步小文件读

**为什么不修**：P3 只要改成"内存与盘取 max"（三行），风险低——但它和**跨进程正确性**绑着，
这轮已经改过一次游标（v0.78 的分文件），再动要重新量并发。
P4 要给一批状态小文件加统一 TTL 层，属于结构改动。
**触发条件**：单轮注入 `ms.total` 超过 200ms。

### B5（💭）`searchPoints` 摘录偏移量错位

`indexOf` 在 `hay` 上找，切片却对折叠空白后的 `text` 做。**只影响摘录偶尔切偏**，不影响命中。
**触发条件**：出现"摘录里看不到关键词" → 两行修（先折叠再 indexOf）。

### B6（💭）三个无淘汰的内存 Map

`sessionModes` / `_sessions` / `perAgent`。常驻进程会缓慢增长。
**触发条件**：多工作区切换后 RSS 持续上涨 → 给 `_sessions` 加 LRU（上限 64）。

### 二轮次要清单（约 25 条）

评审给了清单（`render.js` 的预算/转义、`forget.js` 的 demote、`zip.js` 的 EOCD、
`vault.js` 的 CRLF 等）。**为什么不一起修**：单条影响小，但合成一次提交就没法单独回滚。
**做法**：碰到哪个文件就顺手修哪个，每条带一个最小用例。

## 三、上一版遗留（v0.79.0 就在这里的）

### R5（P2）`hash` 不覆盖 `scope` / `mode`

改 `hashOf` 会让**所有历史档案**验链报红。正确修法是版本化（`hash_v: 2`）。
**触发条件：接群之前。**

### N2（P3）dashboard 的 CSP 里 `script-src 'unsafe-inline'`

真正的防线是 `textContent`（页面没有把数据插进 script 的地方）。
**触发条件**：dashboard 要渲染用户可控的链接/HTML。

### N3（P3）中和标题时插入的零宽字符会跟着导出走

只影响"看起来像标题"的字符串，磁盘原文不动。
**触发条件**：做"导出记忆库为 markdown"时先剥掉 `\u200b`。

## 一句话

**这轮修的都是"线断了"（一行级），没修的都是"要重新设计"或"要先量"。**

评审那句批评我接受：**`catch { /* 不影响主流程 */ }` 让最简单的 ReferenceError
和"设计取舍"享受了同等待遇。** 从 v0.81.0 起，新增的 catch 要写明"预期何时走到这里"——
写不出来的，至少 `logger.debug` 一行。
