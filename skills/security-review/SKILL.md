# 技能：security-review（审自己的代码，不动别人的）

> 给 agent 用的**过程技能**，不是攻击工具。它在"要判断这段代码有没有安全问题时"被调用。
> 核心立场：**只审授权的代码、只做只读分析、不自动"修"、结论必须带证据。**
> 配套的可执行检查器：`node scripts/audit-self.mjs`（静态、离线、零依赖）。

## 何时用

- 改动涉及**注入面**（任何会进模型 prompt 的文本）
- 改动涉及**记忆的写入/删除/迁移**（`10_archive` / `30_points` / `00_core`）
- 改动涉及**文件路径解析**（库在哪、备份写哪、`--dir` 从哪来）
- 引入**新依赖**、新的网络调用、新的子进程
- 用户说"帮我看看有没有漏洞"（这时**先问清楚是审哪个目录**，不要猜）

## 何时**不要**用

- 目标不是你自己拥有或书面授权的系统 → 停下，说明原因。
- 目标是第三方站点、别人的仓库、生产环境 → 停下。这个技能只做**本地只读审查**。
- 用户想要"自动修复漏洞" → 不做。只给"证据 + 建议 diff"，由人决定。

## 检查清单（按这七层走，别跳）

### 1. 注入面（本项目最贵的教训）

- [ ] 新增的"进模型"出口有没有过 `sanitizeForPrompt()`？现有出口：正文三级渲染、工作记忆、索引层、dormant 行、场景展开、`memory_recall` 回查、`digest` 原文包、自述块。
- [ ] 块边界标记（`<!-- 记忆 -->` / `<!-- /记忆 -->`）在输出里**只出现一次**？内容里的 `<!--` 必须被拆开。
- [ ] 记忆内容里能不能伪造出"系统指令"的样子？（围栏声明在不在最前面）
- [ ] 记忆内容有没有被当成**路径**、**命令**、**SQL**、**URL** 使用？（本项目禁止）

### 2. 真相层不可变

- [ ] 有没有代码在 `10_archive/` 上做 `writeFileSync` / `truncate` / 重写？（唯一例外是 `memory erase`，它必须重算 hash 链 + 同步备份 + 重写清单 + 留 `erasure.log`）
- [ ] 有没有绕过 `40_pending/` 直写 `30_points/` 的路径？
- [ ] 有没有"原地改旧记忆"的逻辑？（应改用 `invalid_at` 标记，历史保留）

### 3. 归档与完整性

- [ ] 追加写是否仍带 `prev`/`hash`？
- [ ] 并发下是否可能两个进程同时追加、把链写断？（本项目未加跨进程锁，属已知边界，别假装已解决）
- [ ] 完整性清单（`archive-manifest.json`）在"当天正常变长"时会不会误报？

### 4. 秘密与隐私

- [ ] 仓库里有没有 token / 私钥 / 连接串？（正则扫：`sk-`、`ghp_`、`AKIA`、`PRIVATE KEY`、`password=`）
- [ ] 日志里有没有绝对路径、用户名、完整 query？（本项目规定只记目录名）
- [ ] 备份是不是明文？（是。要在文档里明说，不能让用户以为已加密）

### 5. 依赖与供应链

- [ ] `package.json` 的 `dependencies` 是否仍为空？（零依赖是契约）
- [ ] 有没有把别人的代码拷进来？拷进来的许可证是什么？（**AGPL 会传染**，`_refs/`、`vendor/` 是重点）
- [ ] 有没有 `postinstall`、`eval`、`new Function`、`pickle.load`、`yaml.load(` 这类可执行面？

### 6. 网络与遥测

- [ ] `lib/` 里有没有 `fetch(` / `http.request` / `https.request`？
- [ ] 有没有"上报""统计""埋点"字样？
- [ ] 唯一允许联网的是**用户手动触发的 CLI**（`upload-release.mjs` 这类），且必须在文档里说明它连哪。

### 7. 错误处理与降级

- [ ] `catch` 里是不是静默 `/* ignore */`？如果是，**这条错误会不会让人以为成功了**？（mem0 的教训）
- [ ] 读不出来的记忆点会不会被静默跳过？（本项目已改为 `skipped` + `check` 硬失败）
- [ ] 失败时的默认值是不是"更危险的那个"？（如：解析失败返回 `{}` vs 抛错）

## 误报识别（先排除这 10 种，再报）

1. 测试夹具里的假 token（`sk-test123`、`ghp_xxx`）→ 看路径是否在 `test/`、`samples/`、且值明显是占位。
2. 文档里的占位符（`<你的用户名>`、`%USERPROFILE%`、`C:\Users\<用户名>`）→ 不是泄漏。
3. 注释里举例的攻击代码 → 看上下文，通常无害；但**注释里的真实密钥一样是泄漏**。
4. `eval` 出现在"禁止 eval"的规则字符串里 → 规则描述不是使用。
5. `child_process` 只出现在文档/测试断言里 → 不算引入。
6. 镜像/第三方 URL 出现在 README → 不是运行时调用。
7. 正则里的 `http://` → 不是请求。
8. `.gitignore` 里被忽略的文件 → 不会进仓库，别当泄漏报。
9. 已归档/已删除的代码路径（git 历史里有、当前没有）→ 除非要求审历史，否则不报。
10. 同一问题在 20 个文件里重复出现 → 合并成一条，列受影响文件，别刷 20 条。

## 报告格式（严格按这个写，别自由发挥）

```markdown
## 结论
一句话：有没有可被利用的问题；如果没有，明说"没发现"，不要为了显得有用而凑。

## findings
| # | 严重度 | 位置 | 问题 | 证据 | 建议 |
|---|---|---|---|---|---|
| 1 | 高/中/低 | `lib/x.js:42` | 一句话 | 引 3–5 行原文 | 具体怎么改 |

## 已排除的假阳性
- `path:line` — 为什么不是问题

## 没查的部分
明确写出边界（没跑的扫描器、没审的目录、需要人工判断的地方）。
```

**硬要求**：

- 每条 finding 必须有**行号 + 原文片段**；写不出证据就不是 finding，是猜测（放"待验证"）。
- 严重度按**可利用性**而不是"看着危险"：能拿到数据/能执行代码/能绕过认证 = 高；需要本机权限、需要用户配合 = 低。
- **不写"可能""大概"**——不确定就说"不确定，需要这样验证：…"。
- 不为了凑数报"缺少安全头""没有 CSRF token"这类**不适用于本项目**的泛化建议。

## 禁止事项

- ❌ 不扫第三方目标、不发任何请求、不跑 nmap/sqlmap 之类工具。
- ❌ 不自动改代码、不自动提 PR、不自动"顺手修一下"。
- ❌ 不把未验证的结论写进 `35_ability/`（那是能力记忆，只收验证过的）。
- ❌ 不把用户的真实记忆内容贴进报告（引用时打码：`msg-xxxx` → `msg-***`）。

## 怎么接入

本技能是**纯文本 + 一份静态检查器**：

```powershell
node scripts/audit-self.mjs                     # 审当前仓库，人读的报告
node scripts/audit-self.mjs --dir ..\x --json    # 审别的目录，机器读
```

想在 DSH 里把它变成"她能主动用"的技能，需要在插件里注册（会改变她的技能列表）：

```js
// lib/index.js，在 fish-remember 那个 skills.register 旁边
host.effect(() => host.skills?.register?.({
  name: 'security-review',
  description: '审自己代码的安全问题（只读、离线、不碰第三方目标）',
  // content: 本文件正文
}))
```

**注册前三思**：技能列表变了 = 她每次都能看到这个入口。要改就显式改，别顺手。
